# 📦 حزمة الملفات المطوَّرة — لوحة تحكم السوبر أدمن

هذه الحزمة تحتوي **كل ملفات التصميم المطوَّرة** في جلسات إعادة التصميم:
سبع صفحات كاملة بهوية بصرية مستقلة لكل صفحة + دعم CSS + إصلاحان
في الخادم + بذور بيانات للمعاينة.

> **المبدأ الحاكم:** كل الصفحات تحتفظ بعقود الـ API الأصلية 100٪
> (نفس مسارات GET/POST/PUT/DELETE، نفس أسماء الحقول، نفس منطق الأعمال) —
> أي أن ملفات الصفحات **drop-in replacement**: انسخها مكان القديمة مباشرة.

## 🛠️ خطوات الدمج في مستودعك الحقيقي

### 1) الصفحات السبع (الأساس — مطلوب)
انسخ محتويات `src/components/admin/` من الحزمة فوق نظيرتها عندك:

```bash
# من جذر مستودعك، بعد فك الحزمة:
cp -r nezam-admin-redesigns/src/components/admin/* src/components/admin/
```

> لا تحتاج أي تعديل في `SuperAdminApp.tsx` — الصفحات تُستورد وتُعرض
> بنفس مفاتيح العرض الحالية (`view`) دون تغيير.

### 2) الأنيميشنات (مطلوب — اختر إحدى طريقتين)
الصفحات تستخدم 3 أنيميشنات مخصصة (مضاف لها كلها `prefers-reduced-motion`):

| الأنيميشن | الصفحة | الوصف |
|---|---|---|
| `ticker-run` | الإيرادات | شريط معاملات يتدفق يساراً (45s)، يتوقف عند hover/focus |
| `radar-sweep` | إعدادات التتبع | مكنسة رادار دوّارة (4s) |
| `flow-strip` | إعدادات التتبع | خط إشارة متقطع متدفق (1.4s) |

- **الطريقة أ (أسهل):** انسخ `src/app/globals.css` من الحزمة مكان نسختك —
  هو نفس ملفك الأصلي تماماً + الأسطر الثلاثة فقط (لو لم تُعدّل globals.css
  منذ رفعك للموقع).
- **الطريقة ب (أأمن لو عندك تعديلات):** افتح `animations-patch.css` وألصق
  محتواه في نهاية ملف `src/app/globals.css` عندك — تعريفات `@keyframes`
  والفئات `.ticker-run/.radar-sweep/.flow-strip` عامة وتعمل من أي موضع.

### 3) إصلاحا الخادم (اختياري لكن مُوصى به)
- **`src/app/api/admin/tracking/utm/route.ts`** — كان البحث (`q`) يستخدم
  `mode:'insensitive'` الخاص بـ PostgreSQL فقط فيُسقط الاستعلام كله على
  محركات أخرى. الآن مُحاط بفحص `describeDbConnection()` — السلوك على
  PostgreSQL (موقعك) لم يتغير إطلاقاً، وأصبح يعمل على أي محرك.
- **`src/lib/tracking/analytics.ts`** — أُضيف `campaignPerformanceOrm`
  كاحتياطي يُستخدم فقط عند فشل الـ SQL الخام (نفس دلالات العدّ بالضبط:
  إزالة تكرار `eventId|eventName|subId` وسلسلة `sub→tenant→user`).
  على PostgreSQL عندك يعمل مسارك الأصلي كما هو.

### 4) بذور المعاينة (اختياري — للتجربة المحلية فقط)
ملفات `demo-seeds/` تُنشئ بيانات عرض واقعية (كودات، معاملات مالية،
قنوات تتبع، حملات UTM). شغّلها بنفس طريقة أي سكربت بذر عندك:
`bunx tsx seed-xxx-demo.ts`. **لا تستخدمها في الإنتاج.**

## ⚠️ ما الذي *لا* تحتاج نقله من بيئة المعاينة

بيئة التطوير هنا (Sandbox) فيها محوّلات خاصة بها **موجودة فقط هناك**
ولا يجب استبدال نظيرك بها — ولم تُضمَّ لهذه الحزمة أصلاً:

- `src/lib/db.ts` · `src/lib/env.ts` · `src/lib/auth.ts` · `src/lib/prisma-wasm.ts`
  (عندك النسخ الأصلية الأفضل — PostgreSQL/Supabase + Cloudflare Workers).
- سطر «default view» الافتتاحي في أعلى `SuperAdminApp.tsx` وزر التحميل
  في الشريط الجانبي — إضافات عرض خاصة بالبيئة التجريبية فقط.
- `prisma/schema.prisma` هنا على SQLite — استخدم مخططك الأصلي.
