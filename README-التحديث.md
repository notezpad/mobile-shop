# تحديث الموارد البشرية — إصلاح الرواتب + تصميم جديد للصفحات السبعة

## ١) إصلاح حساب الرواتب (الأيام الفعلية)

### المشكلة
النظام القديم كان بيعتبر أي يوم من غير تسجيل حضور **"حاضر"** ويصرف الراتب كامل — فالموظف اللي محضرش ولا يوم كان بياخد راتبه كامل (زي حالة الموظف وسام: 3500 جنيه من غير ولا يوم تسجيل).

### الحل الجديد
الحساب بقى على **الأيام الفعلية المسجّلة**:

| اليوم | بيتدفع؟ |
|---|---|
| سجل حضور أو تأخير | ✅ نعم |
| إجازة معتمدة بمرتب (سنوية/مرضية) | ✅ نعم |
| إذن (ساعات) | ✅ نعم — زي ما هو مالوش أثر |
| الراحة الأسبوعية **لو أسبوعها فيه شغل أو إجازة** | ✅ نعم |
| غياب صريح / يوم من غير أي تسجيل | ❌ لأ — بيتخصم |
| الراحة الأسبوعية لأسبوع محدش شغل فيه | ❌ لأ |

### الرسائل الجديدة اللي طلبتها
- **تنبيه أصفر** فوق جدول الرواتب: «فيه N يوم شغل من غير تسجيل حضور — **اتخصموا** من الرواتب» مع زر وصل لشاشة الحضور وتنبيه تاني داخل حوار الصرف قبل الاعتماد.
- **عمود جديد "أيام الشغل"** لكل موظف: «22 من 26 يوم شغل».
- **شارة حمراء** للموظف اللي من غير أي يوم شغل مسجّل.
- **تنبيه أزرق** لو فيه أيام من الشهر لسه جاية: «خصم مؤقت — سجّل الحضور واضغط أعد الحساب».
- **قسيمة الواتساب** بقت فيها أيام الشغل وتفصيل الخصم (غياب + بدون تسجيل).
- **ملف Excel** بقى فيه عمود أيام الشغل.

### نتائج الاختبار (راتب 3500 — شهر 31 يوم)
| السناريو | النتيجة |
|---|---|
| محضرش ولا يوم | **صافي 0** (كان 3500 — دي كانت المشكلة) |
| شغال كل أيام الشهر (26 يوم) | صافي 3500 كامل |
| شغال 13 يوم بس | صافي 1750 |
| غياب صريح يومين | صافي 3150 (خصم يومين) |
| إجازة سنوية بمرتب | الراتب كامل بدون خصم |
| معيّن 15 من الشهر | الأساسي بيتناسب (17/31) |
| قسط سلفة 500 | بيتخصم من الصافي عادي |

## ٢) التصميم الجديد للصفحات السبعة

نفس لغة تصميم لوحة التحكم الرئيسية (الهيرو المتدرّج + شريط الأرقام الموحّد + الشارات بالنقاط)، وكل صفحة ليها **هوية لونية وأيقونة تعبّر عن دورها**:

| الصفحة | اللون | الأيقونة | الهوية |
|---|---|---|---|
| الموارد البشرية (الرئيسية) | الأخضر الأساسي | HeartHandshake | مركز القيادة + كروت الوحدات الست |
| الموظفين | أزرق Info | Users | دليل الموظفين + إحصائيات (رواتب إجمالية / PIN / سلف) |
| الحضور والانصراف | كهرماني Warning | MonitorSmartphone | زمنية — عدّادات اليوم + أزرار الحالة |
| الإجازات | تركواز | CalendarDays | أرصدة بشرط تقدم ملونة |
| التقييمات | بنفسجي | Award | نجوم + أشرطة درجات الحضور + لوحة «اسأل» |
| السلف | أحمر Danger | HandCoins | شرائط تقدم السداد بالأحمر |
| الرواتب | الأخضر الأساسي | Wallet | جدول أيام الشغل + التنبيهات |

كل الصفحات:
- بتشتغل بنفس **الوضع الليلي** والتوكنات الموجودة (مفيش ألوان جامدة).
- **متجاوبة** للجوال (شريط الأرقام بيتحول لصفوف) والكشك والواجهات القديمة شغالة زي ما هي.
- المنطق والـ APIs **زي ما هي بالظبط** غير منطق الحساب الموصوف فوق.

## ٣) طريقة التطبيق

الملفات المعدّلة (١١ ملف) — انسخها بنفس المسارات فوق الموجود عندك:

```
src/lib/hr.ts                                  ← منطق الحساب (countPaidDays + computePayslip)
src/lib/hr-payroll.ts                           ← تجميع أيام الشغل عند توليد المسودة
src/app/api/hr/payroll/[id]/route.ts            ← إرجاع أيام الشغل والتنبيهات
src/components/shop/hr/hr-ui.tsx                ← kit التصميم (HrHero + StatStrip + Panel...)
src/components/shop/hr/HrHomeView.tsx
src/components/shop/hr/HrEmployeesView.tsx
src/components/shop/hr/HrAttendanceView.tsx
src/components/shop/hr/HrLeavesView.tsx
src/components/shop/hr/HrEvaluationsView.tsx
src/components/shop/hr/HrAdvancesView.tsx
src/components/shop/hr/HrPayrollView.tsx
```

### ⚠️ خطوة مهمة بعد النشر
لو عندك **مسودة رواتب موجودة** (زي مسودة أكتوبر):
1. افتح صفحة الرواتب.
2. اضغط **«أعد الحساب»** — المسودة القديمة اتحسبت بالمنطق القديم ولازم تتولد تاني بالأيام الفعلية.

مفيش أي تغيير في قاعدة البيانات (schema) — التحديث كله كود، فمش محتاج migration.

## ٤) ملاحظات

- **الطلبات المدفوعة القديمة** (الدورات المتصرفة) مش بتتأثر — الحساب الجديد بيتطبق على المسودات الجديدة وإعادة الحساب.
- **درجة الحضور في التقييمات** لسه بتعتبر اليوم غير المسجل "حاضر" (زي ما كانت) — لو عايز أغيّرها بنفس المنطق الجديد قولّي.
- الاختبارات: `tsc --noEmit` ✅ + `next build` إنتاجي كامل ✅ + ١٠ سناريوهات حسابية مريحة ✅.
