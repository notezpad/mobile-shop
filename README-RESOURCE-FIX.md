# سبب سحب الموارد + الإصلاح (nezampos)

## السبب الرئيسي (٩٠٪ من الاستهلاك)
ملفات الموقع الثابتة (JS / CSS / خطوط / أيقونات) كانت بتترجع من Cloudflare بهيدر:

    cache-control: public, max-age=0, must-revalidate

يعني **المتصفح ممنوع يخزّن أي ملف**. كل فتح صفحة أو تنقّل بين الصفحات = ٢٥-٣٠
ريكويست جديد على الـ Worker لنفس الملفات اللي مش بتتغير أصلاً (أسماءها فيها hash).
ده بالظبط اللي ظاهر في الميتريكس: `assets.local` = ‎24.5k‎ ريكويست في الساعة،
و Invocations ≈ نفس الرقم.

**الإصلاح:** ملف جديد `public/_headers` يخلي `/_next/static/*` تتخزن سنة
كاملة `immutable` → بعد أول تحميل صفر ريكويست لنفس الملفات.

## أسباب مساعدة (الاستهلاك "بدون تصفح")
1. **الـ Service Worker** كان بيعمل stale-while-revalidate لكل ملف static:
   بيرجّع النسخة المخزنة **وكمان يعمل ريكويست شبكة لنفس الملف** في كل مرة.
   → بقى cache-first لملفات `/_next/static/`. (وكمان ممنوع تخزين `/api/auth/*`).
2. **مؤقتات تسحب داتا وأنت مش بتعمل حاجة** (لكل تاب مفتوح):
   - الإشعارات كل ٣ دقائق → **١٠ دقائق**
   - لوحة المعلومات كل ٥ دقائق → **١٥ دقيقة** + مش بتحدّث لو التاب مخفي
   - الرجوع للتاب كان بيعمل تحديث فوري كل مرة → **مرة كل ٥ دقائق كأقصى**
   - محرّك الأوفلاين كان بيسحب **كل المنتجات + ٨ endpoints كل ٥ دقائق** →
     **كل ٢٠ دقيقة**
3. **زوار/بوتات غير مسجّلين** كانوا بيكلّفوا ٢-٣ ريكويستات + اتصالات قاعدة بيانات
   (`/api/auth/me` + `/api/tenant` + `/api/subscription`) لكل زيارة.
   → دلوقتي `/api/tenant` و `/api/subscription` بينده **فقط** بعد التأكد إن فيه
   سيشن حقيقي.

## طريقة التطبيق
انسخ الملفات دي فوق مشروعك بنفس المسارات، ثم:

    npx opennextjs-cloudflare build && npx wrangler deploy

بعد النشر اتأكد من الهيدر:

    curl -I https://<domain>/_next/static/chunks/<any>.js
    # المطلوب: cache-control: public, max-age=31536000, immutable

نسخة الكاش في الـ Service Worker اتغيرت (v3 → v4) فالأجهزة هتحدّث نفسها تلقائياً.

## نصيحة إضافية (اختيارية)
لو لسه فيه ريكويستات غريبة بدون مستخدمين، افتح Cloudflare → Workers →
nezampos → **Observability / Logs** وشوف الـ User-Agent و الـ path الأكثر
تكراراً — لو بوتات، اعمل WAF rule يقفل الزحف على `/api/*`.
