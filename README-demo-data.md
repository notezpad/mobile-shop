# 🎁 البيانات التجريبية لأول دخول — Nezam POS

## المشكلة
`/api/auth/signup` كان بينشئ محل + أدمن + اشتراك تجريبي **بس**، فكل عميل جديد يفتح لوحة تحكم صفرية.

## الحل
عند التسجيل بيتزرع محل تجريبي كامل حسب نشاط الباقة (إلكترونيات / ملابس / غذائية): 6–10 منتجات (بألوان/مقاسات للملابس، بالوزن للغذائية)، 5 عملاء، 3 موردين، 3 أوامر شراء، ~35–45 فاتورة آخر 14 يوم (منها آجل)، تحصيل وسداد، مصروفات، فرع رئيسي، وأوامر صيانة للإلكترونيات.
- الزرع بيمر على `create_purchase_order` و `create_sale` الأصليتين → المخزون والخزنة والديون بنفس قواعد النظام.
- كل صف تجريبي متسجّل في جدول `DemoRecord` → زر **«امسحها»** بيمسح التجريبي بس، وبيحمي أي صف حقيقي مربوط بيه.
- العملاء اللي سجّلوا قبل كده (محلاتهم فاضية) بيظهرلهم زر «حمّل بيانات تجريبية» في لوحة المعلومات.
- الأسماء التجريبية فيها «(تجريبي)» والمستخدم التجريبي معطّل وباسورده غير صالح (مستحيل حد يدخل بيه).

## التركيب (بالترتيب)
1. Supabase → SQL Editor → الصق `prisma/sql/demo-data-v1.sql` كله → Run (بعد create-sale / create-purchase-order / seasonal-v1). بينشئ الجدول والدوال.
2. انسخ الملفات الجديدة:
   - `src/lib/demo-data.ts`
   - `src/app/api/demo/route.ts`
   - `src/components/shop/DemoDataBanner.tsx`
   - `prisma/migrations/20261023_demo_data/` (للتوثيق)
3. طبّق التعديلات على الملفات الموجودة: `patch -p1 < demo-data.patch`
   (schema.prisma · signup/route.ts · signup/page.tsx · (shop)/layout.tsx · admin-fake-tenants.ts) — أو انسخ النسخ الجاهزة من نفس المسارات.
4. `npm run build` ثم انشر.

## ملاحظات
- لو الخطوة 1 ما اتعملتش، التسجيل يشتغل عادي (الميزة fail-open) والمحل يفضل فاضي.
- المنتجات المحمية من المسح بتفضل بكمية صفر، والعملاء المحمية بيتصحح رصيدهم.
- كاش الحافة (Edge Cache) بيتمسح بعد الزرع/المسح؛ الموظفين في فروع تانية ممكن يشوفوا القديم لحد انتهاء الـ TTL.
- التخصيص: كل الأسماء والأسعار في أعلى `demo-data.ts` (CATALOGS). البيانات ثابتة (seed ثابت) فنفس النتيجة كل مرة.
- لوحة الأدمن: المحلات «تجريبية فقط» بقت تظهر في تنظيف الحسابات الوهمية زي المحلات الفاضية.
- الاختبار: اتجرّب على Postgres 16 بنفس هيكل الجداول للأنشطة التلاتة: مخزون مش سالب، الخزنة ≥ 0 طول الوقت، أرصدة العملاء = الفواتير − الدفعات، أرقام الفواتير بلا تكرار، والمسح بيرجّع المحل لحالته الأولى.
