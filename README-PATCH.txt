■ أول حاجة — اللي حصل ليه المشكلة فضلت موجودة بعد v10؟

  بصراحة: إصلاح الجذر كان جاهز في ملفات الشغل، لكن ماوصلش معاكم —
  الـ PATCH v10 شال تعديلات الكود (الكاش + الحمولات) وده قلّل الضغط،
  لكن القطعة الأهم (اللي بتشيل سبب الـ 1102 من أصله) ماكانتش ضمن
  الملفات اللي وصلتكم. سوريو، ودي النسخة اللي فيها كل حاجة.

■ الدليل القاطع من سجلات موقعكم الحقيقية (wrangler tail):

  GET /api/customers              - Exceeded CPU Limit
  GET /customers?_rsc=...         - Exceeded CPU Limit   ← صفحة!
  GET /expenses?_rsc=...          - Exceeded CPU Limit   ← صفحة!
  GET /api/branches               - Exceeded CPU Limit   ← أصغر API!
  X [ERROR] Error: Worker exceeded CPU time limit.

  لاحظوا: حتى /api/branches (استعلام صغير جدًا) قعت! ده معناه إن
  المشكلة مش في استعلام معين — المشكلة إن **رندر الصفحات نفسه**
  (React SSR كامل) بيحصل جوا الـ Worker في كل زيارة، وده بياخد
  وقت CPU أكتر من حد الخطة المجانية (10ms) — فأي تصفح سريع بيبعت
  طلبات كتير مع بعض → العزل (isolate) بيتخنق → كل الطلبات اللي عليه
  بتفشل دفعة واحدة → الأصفار + الموقع بيقع → بعد ثواني بيرجع لوحده.

■ السبب الجذري بالتفصيل:

  كل صفحات النظام (36 صفحة: /inventory، /dashboard، /customers...)
  معمولة prerender وقت البناء وبتتخزن جاهزة في ملفات الكاش — لكن
  الكونفيج القديم كان بيستخدم الكاش الافتراضي (ذاكرة داخلية بتفرغ
  مع كل isolate جديد). النتيجة: أول طلب لكل صفحة بعد ما Cloudflare
  تقلّب العزل = Next.js يرندر الصفحة من الصفر جوا الـ Worker
  (React SSR كامل = 10-30ms CPU) → بيعدي الحد → 1102.

  يعني المشكلة كانت مش في قاعدة البيانات ولا في كود الشاشات —
  كانت في إن الصفحات الجاهزة كانت بتترندر تاني من الأول في كل مرة
  بدل ما تتقرأ جاهزة!

■ طريقة التركيب (مهم — الترتيب الجديد):

  1) فك ضغط الملف
  2) انسخ الملفات الثلاثة فوق نسختك بنفس المسارات:
       open-next.config.ts               ← في جذر المشروع
       package.json                      ← في جذر المشروع
       scripts/populate-cache-assets.mjs ← جوه مجلد scripts
  3) البناء والنشر — اختار واحدة:

     الطريقة السهلة (أمر واحد جديد بيعمل كل حاجة):
        bun run cf:deploy

     أو بالتفصيل (لو حابب تشوف الخطوات):
        bun run cf:build
        bun run cf:populate      ← دي الخطوة الجديدة المهمة
        node node_modules\wrangler\bin\wrangler.js deploy

     ملاحظة: بنستخدم مسار node مباشر بدل npx wrangler عشان
     Windows Device Guard على جهازكم بيحجب wrangler.exe —
     تجربة tail نفسها اثبتت إن الطريقة دي شغالة عندكم.

  4) بعد النشر: افتح الموقع وتصفح عادي. أول زيارة لكل صفحة
     بعد النشر هتاخد شوية — وبعدها كل التنقلات فورية تقريبًا.
