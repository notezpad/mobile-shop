  PATCH v10 — إصلاح جذري لـ Error 1102 (Worker exceeded resource limits)
  نظام المحل — nezampos.com — 2026-10-06
════════════════════════════════════════════════════════════════════

■ المشكلة اللي اتفضلت الإشارة ليها:
  الصفحات بقت سريعة جداً (بعد v9) — بس بعد تصفح كام صفحة، فتح المخزون
  تاني يلاقي الأرقام صفر، وعمل Refresh يظهر «Error 1102 — Worker
  exceeded resource limits» والموقع بيقع فترة.

■ السبب الجذري (اتشخّص من الكود نفسه — 4 عوامل متراكبة):

  1) صفحة المخزون كانت بتطلق 5 طلبات API متوازية في *كل* زيارة، اتنين
     منهم غير محدودين:
       • /api/products?limit=1000&status=all  (بدون كاش + groupBy ثقيل
         على عناصر الفواتير + حساب تسعير لكل منتج)
       • /api/inventory/movements             (حتى 1000 حركة كاملة)
     يعني كل فتح مخزون = استعلامات ضخمة + تسلسل JSON لحوالي 300KB —
     وده كان بيتمكر على الـ Worker (حد الباقة المجانية).

  2) الـ Service Worker كان بيخزّن في الكاش *أي* رد — حتى صفحات الخطأ!
     صفحة Error 1102 نفسها كانت بتتخزن تحت رابط الصفحة/الـ API، فالموقع
     كان بيفضل «واقع» من الكاش بعد ما يتعافى، والأصفار بتفضل ظاهرة
     لحد ما المستخدم يمسح الكاش بنفسه. (ده سبب «الأصفار» بالظبط:
     الطلب بيفشل → الواجهة بتستقبل رد خطأ أو فاضي → بتعرض صفر بصمت).

  3) كل طلب API كان بينشئ PrismaClient جديد + محرك الاستعلام من الصفر.
     (جربنا نوحّده لكل isolate — لكن بيئة Cloudflare Workers بتربط
     الاتصالات بسياق الطلب، فده مش ممكن تقنياً — التقليل بقى عن طريق
     تقليل عدد الطلبات الباردة نفسها، وشوف البند 4).

  4) استعلام Tenant (المنطقة الزمنية) كان بيتكرر في كل طلب داشبورد/
     تقارير/مخزون من غير داعي.

■ الحل في v10 (13 ملف):

  ✅ صفحة الحركات (/inventory/movements):
     - الـ API بيرجّع 50 حركة/صفحة من السيرفر (بدل 1000) — الحمولة
       نزلت من ~300KB لـ ~18KB (-94%)
     - ميزان الحركة (وارد/صادر) ومنحنى آخر 14 يوم بيتحسبوا دلوقتي
       جوه PostgreSQL (SUM/GROUP BY) — والأرقام بقت أدق كمان (كانت
       بتتحسب على آخر 1000 حركة بس، دلوقتي على كل الحركات)
     - التنقل بين الصفحات بقى طلب خفيف من السيرفر
     - كاش حافة 15 ثانية + مسح فوري بعد تسجيل أي حركة

  ✅ منتجات شاشة المخزون:
     - meta=slim: استعلامين كاملين اتحذفوا من كل تحميل مخزون
       (soldQuantity groupBy + التسعير الديناميكي — الشاشة مش بتستخدمهم)
     - كاش حافة 20 ثانية لنفس الاستدعاء — زيارات المخزون المتتالية
       بترجع ≈ بصفر CPU
     - أي بيع/تعديل منتج/حركة بيمسح الكاش فوراً — الكميات حية

  ✅ Service Worker (أهم إصلاح لعرض الأصفار):
     - ممنوع تخزين أي رد غير ناجح (صفحات 1102/5xx مش بتتخزن خلاص)
     - لو الـ API رجّع 5xx، بيتقدّم آخر نسخة سليمة (لو أحدث من 60
       ثانية) بدل الأصفار — بيانات قديمة بثواني أحسن من شاشة فاضية
     - رقم نسخة الكاش اترفع (v5) عشان النسخة القديمة المعيوبة تتمسح
       تلقائياً عند أول تحميل بعد التحديث

  ✅ كاش المنطقة الزمنية للمحل (5 دقايق) — استعلام أقل في كل طلب

  ✅ كل تعديلات v7/v8/v9 محفوظة زي ما هي (تم التحقق من البناء النهائي:
     قواعد الموبايل 639.98px ✓ / مفيش scrollbar transition ✓ /
     cv-heavy ✓ / focus preventDefault ✓ / edgeCache ✓)

■ نتائج الاختبار المحلي (بيانات اختبار: 1005 منتج + 5207 حركة):
  - E2E كامل (موبايل iPhone 14 + إبطاء CPU 6x): 14/14 ناجح

  - مفتاح كاش بعد الحركة بيتمسح صح (العدد بيتحدث فوراً)
