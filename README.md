# nezampos — PATCH v17 (مفيش بيانات مختفية بصمت بعد النهاردة)

## المشكلة اللي بتحلها
بعد تركيب v16 صفحة الحركات بقت تفتح طبيعي (الشاشة السوداء اتحلت)، لكن القايمة
بتظهر **فاضية تماماً**: لا حركات بيع ولا شراء ولا أي حاجة — حتى حركة بيع جديدة
بتتعمل من نقطة البيع مبتظهرش.

**السبب الجذري:** v16 عالج الكراش بس خلى فشل التحميل **صامت**: أي رد غلط من
الخادم (خطأ 500، اشتراك 402، رد فاضي…) بيتحول بهدوء لقائمة فاضية — فبدل
الشاشة السوداء القديمة بقى عندك «دفتر فاضي» من غير أي رسالة توضح السبب.
وفيه كمان سببين مكمّلين اتقفلوا في النسخة دي:
1. **Service Worker كان بيخزّن ردود الأخطاء نفسها** (حتى 500) ويرجّعها لاحقاً
   بدل البيانات الحقيقية — فالخطأ القديم ممكن يفضل يعيش على جهازك.
2. **الخادم كان مميرجّعش كود خطأ حقيقي** في حالة نادرة أثناء التحقق من الجلسة:
   كان يردّ 200 بجسم فاضي (العميل يفهمها «مفيش بيانات») بدل 500 واضح.

## الإصلاح (10 ملفات — استبدال مباشر)
1. **src/lib/auth.ts** — الإصلاح الجذري: أي خطأ تحقق غير معروف دلوقتي يرجّع
   **500 حقيقي بجسم JSON واضح** بدل 200 فاضي — ده بيفعّل نفس الإصلاح في **كل
   مسارات التطبيق مرة واحدة** (الحركات/التحويلات/الجرد/الفروع/المنتجات/…).
2. **public/sw.js** — كاش الـ API بقى يخزّن **الردود السليمة فقط**، وأي رد خطأ
   مايتخزنش خالص، ولو الجهاز ققطع إنترنت بنرجّع نسخة سليمة معروفة فقط أو
   رسالة «غير متصل». ورفعنا رقم الكاش v4→v5 فأول تشغيل بعد النشر بينضف
   **كل الكاش القديم تلقائياً** (بينهي أي بيانات قديمة متراكمة).
3. **useInventoryData.ts** — بيتبع سبب فشل كل مصدر تحميل (رمز HTTP / شبكة /
   رد غير متوقع) وبيعرضه للصفحات بدل ما يبلعه.
4. **shared.tsx** — مكوّن جديد `LoadErrorBanner`: بانر أحمر واضح فيه سبب
   الفشل + زر «إعادة المحاولة».
5. **MovementsTab.tsx / MovementsPage.tsx** — دفتر الحركات بقى بيفرّق بين
   حالتين: «الدفتر فاضي فعلاً» (رسالة عادية) و«فشل التحميل» (بانر أحمر
   بالسبب + إعادة محاولة). ولو فشل تحديث الحركات وهي ظاهرة، بنسيب البيانات
   المعروضة ونضيف البانر فوقها — مفيش اختفاء مفاجئ.
6. **StockPage / TransfersPage / StocktakePage** — نفس البانر في صفحات
   المخزون/التحويلات/الجرد (نفس المرض نفس الدوا).

## إزاي تركّبها
1. انسخ مجلدَي `src` و`public` اللي في الحزمة فوق مشروعك (استبدال مباشر).
2. اعمل push — Cloudflare هيبني لوحده (مفيش deps جديدة ولا تغيير قاعدة بيانات).
3. بعد النشر: افتح الموقع واعمل **تحديثين عاديين** (أول تشغيل بينشّط كاش v5
   وينضف القديم) — ولو ظهرت رسالة «اتنشرت نسخة جديدة» اضغط تحديث.

## بعد التركيب — هتعرف السبب الحقيقي فوراً
افتح صفحة الحركات وقولي إيه اللي ظهر:
- **الحركات ظهرت كلها** → كان الكاش القديم هو السبب وانحل.
- **بانر أحمر «الخادم ردّ برمز 402»** → الاشتراك منتهي — جدّد من صفحة الاشتراك.
- **بانر «الخادم ردّ برمز 403»** → المشكلة في باقتك مش في البيانات.
- **بانر «الخادم ردّ برمز 500»** أو «رد غير متوقع» → اضغط «إعادة المحاولة»
  (لو ظهرت مع أكتر من محاولة، ابعتلنا البانر اللي ظهر بالظبط).
- **«الدفتر لسه فاضي» من غير أي بانر** → السيرفر رجّع 0 حركات فعلاً —
  ساعتها يبقى الفحص مطلوب في قاعدة البيانات نفسها، والحزمة دي كلها مش هيخفي عنك السبب.
- **فحص إضافي (اختياري)**: وانت مسجّل، افتح عنوان
  `nezampos.com/api/inventory/movements` في تاب جديد — لو شفت أرقام JSON
  يبقى الخادم سليم والمتصفح هو اللي كان مخزّن قديم؛ ولو شفت رسالة خطأ
  ابعتلنا نصها.

## إثبات الإصلاح (34/34 ✅)
- خادم بيردّ 500: بانر «الخادم ردّ برمز 500» ظهر + زر إعادة محاولة + مفيش
  «الدفتر لسه فاضي» الكاذبة + الصفحة عايشة وصفر أخطاء JS.
- الرد القاتل القديم (200 + object خطأ): بانر «رد غير متوقع من الخادم»
  والصفحة ثابتة (نفس السيناريو اللي كان بيعمل الشاشة السوداء في v14).
- رد 200 بمصفوفة فاضية فعلاً: «الدفتر لسه فاضي» الصادقة فقط، بدون أي بانر.
- فشل 500 ثم نجاح بعد ضغط «إعادة المحاولة»: الحركات ظهرت والبانر اختفى.
- بيانات سليمة (من ضمنها صفوف عدوانية: منتج محذوف، كمية كنص، كمية null):
  اترسمت كلها، حركة البيع «فاتورة INV-1024» ظاهرة، وميزان الحركة عرض
  +2,500,024 كاملة، وثبات 15 ثانية على موبايل 360px بصفر أخطاء وصفر فيض أفقي
  في الصفحات الأربعة موبايل وديسكتوب.
